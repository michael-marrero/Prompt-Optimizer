<objective>
Wave 5 of Phase 3 — author blob storage transcoder + extend `routes/turn.py` to externalize Screenshots ≥256 KB + extend `db/queries.delete_thread` to cascade-unlink blob files BEFORE the DB delete.

Purpose: STORE-04 requires that large screenshots and diffs are written to `~/.prompt-optimizer/blobs/<sha256>.<ext>` rather than embedded inline as base64 in the SQLite `content_blocks` JSON. The transcoder runs inside the turn handler's event_stream BEFORE the chunk is buffered or yielded — so the wire and the DB both see the `image_ref` shape for large content. Cascade unlink is the cleanup side: deleting a thread walks every message's `content_blocks` JSON, collects every `image_ref` / `diff_ref`, unlinks the files, then runs the DB cascade DELETE. Order matters (per D-14): blobs FIRST so an interrupted delete leaves orphan blobs (recoverable by a future `make gc-blobs`) rather than stale DB refs pointing to missing files.

  - 1 new test file: `apps/api/tests/test_blobs_by_hash.py` with 5+ unit tests.
  - 1 test file extension: `apps/api/tests/test_threads_crud.py` adds `test_delete_unlinks_blobs`.
  - The Phase 2 + Phase 3 Waves 0-4 non-live test suites all stay green.

- Defense against tampered DB content_blocks: only allow unlink of paths actually inside BLOBS_DIR.
- `try: resolved = Path(path).resolve(); blobs_resolved = BLOBS_DIR.resolve(); return str(resolved).startswith(str(blobs_resolved) + ("/" if not str(blobs_resolved).endswith("/") else "")); except Exception: return False`.

`def _maybe_externalize_screenshot(chunk: Screenshot) -> Screenshot`:
- If `chunk.image_b64 is None`: return chunk unchanged.
- `raw = base64.b64decode(chunk.image_b64)`.
- If `len(raw) < INLINE_THRESHOLD_BYTES`: return chunk unchanged.
- `sha = hashlib.sha256(raw).hexdigest()`.
- `ext = chunk.image_format` (`"png"` or `"jpeg"`).
- `target = BLOBS_DIR / f"{sha}.{ext}"`.
- If `not target.exists()`:
  - `BLOBS_DIR.mkdir(parents=True, exist_ok=True)`.
  - `tmp = target.parent / f"{target.name}.{secrets.token_hex(4)}.tmp"` (unique per write per Pitfall 11; protects against race on shared tmp name when two turns concurrently produce identical content).
  - `tmp.write_bytes(raw)`.
  - `tmp.replace(target)` (atomic on POSIX + Windows when same filesystem).
- Return `chunk.model_copy(update={"image_ref": str(target), "image_b64": None})`.

`def _collect_blob_refs_from_content_blocks(content_blocks_json: str) -> list[Path]`:
- `try: blocks = json.loads(content_blocks_json); except json.JSONDecodeError: return []`.
- `refs = []`.
- For each `block in blocks`:
  - If `isinstance(block, dict) and block.get("image_ref"): refs.append(Path(block["image_ref"]))`.
  - If `isinstance(block, dict) and block.get("diff_ref"): refs.append(Path(block["diff_ref"]))` (forward-compat for future large-diff externalization; v1 only ships image_ref).
- Return refs.

NEVER use `os.rename()` (PATTERNS anti-pattern) — `Path.replace` is the cross-platform-safe atomic move.
NEVER share a `.tmp` name across writes (Pitfall 11 — concurrent writes of identical content corrupt the tmp file).

async def delete_thread(db, thread_id: str) -> bool:
    """Delete a thread and cascade-unlink any referenced blob files.

    Order matters (D-14):
    1. SELECT content_blocks for every message in the thread.
    2. Walk the JSON to collect every image_ref / diff_ref path.
    3. Path-traversal-defensively unlink each file inside BLOBS_DIR.
    4. THEN run the DB DELETE (FK CASCADE handles messages + routing_decisions).

    Rationale: blobs FIRST means an interrupted delete leaves orphan blobs
    (recoverable by a future `make gc-blobs`) rather than stale DB rows
    pointing to missing files.
    """
    # Step 1: collect blob refs from this thread's messages.
    async with db.execute(
        "SELECT content_blocks FROM messages WHERE thread_id = ?",
        (thread_id,),
    ) as cur:
        rows = await cur.fetchall()
    refs_to_unlink = []
    for row in rows:
        refs_to_unlink.extend(_collect_blob_refs_from_content_blocks(row[0]))

    # Step 2: unlink each ref inside BLOBS_DIR (T-03-Path defense skips paths outside).
    for ref in refs_to_unlink:
        if _is_inside_blobs_dir(ref):
            ref.unlink(missing_ok=True)
        else:
            logger.warning(
                "skipping unlink of out-of-bounds blob ref: %s", ref,
            )

    # Step 3: DB DELETE — FK CASCADE handles messages + routing_decisions.
    async with db.execute(
        "DELETE FROM threads WHERE id = ?", (thread_id,),
    ) as cur:
        deleted = cur.rowcount > 0
    await db.commit()
    return deleted

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `Screenshot.image_b64 → filesystem write` | Bytes from Phase 2 adapter (Anthropic computer-use); content is screenshots of browser-visible web pages. No filesystem traversal possible — sha256 hex hash is the only filename component. |
| `messages.content_blocks → filesystem unlink` | Content_blocks is JSON produced by Phase 3 itself (Wave 4 buffer → JSON in persist_turn). A tampered DB row could try to redirect `image_ref` to `/etc/passwd`; defense: `_is_inside_blobs_dir` resolve-real-path check before unlink. |
| `concurrent writes to identical content` | Two turns concurrently emitting the same Screenshot bytes → same sha256 → same target path. Unique `secrets.token_hex(4)` tmp suffix prevents race on the .tmp file (Pitfall 11). Race on the final `tmp.replace(target)` is benign — both writes produce identical content; whichever replace runs last wins, file is correct. |

SEVERITY: HIGH (without the guard, a tampered DB could trigger arbitrary file deletion). |
