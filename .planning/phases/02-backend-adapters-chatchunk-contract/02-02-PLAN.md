<objective>
Implement the Claude Code adapter — async build-and-edit backend using `claude_agent_sdk.ClaudeSDKClient` (NOT the deprecated `claude-code-sdk` package; NOT the standalone `query()` function). Streams `TextDelta`/`ToolCall`/`ToolResult`/`FileDiff` chunks for each tool the agent executes, enforces per-iteration step cap (default 25) and per-turn cost cap, propagates cancellation via `client.interrupt()`, runs in a per-thread `tempfile.mkdtemp` workspace (with opt-in `cwd` override per BACKEND-08), and sets `CLAUDE_ENABLE_STREAM_WATCHDOG=1` at module import.

Purpose: BACKEND-04 — the Claude Code adapter is the build-and-edit backend (Claude Sonnet/Opus via the `claude_agent_sdk`). It is the most complex adapter (tool execution, subprocess lifecycle, workspace management, stream watchdog). Choosing `ClaudeSDKClient` over the standalone `query()` function is the critical research finding for BACKEND-07 cancellation (Pitfall 2).

  - The Wave 0 D-19 contract suite passes for the `claude_code` parameterization (all 6 invariants).
  - `python -m apps.api.backends.claude_code --prompt "..."` is callable end-to-end.
